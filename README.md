# AI на роботі — практичний гід

Односторінковий сайт-інструктаж для співробітників: як користуватись корпоративним GPT, який AI обирати для задачі, як писати ефективні промти та які правила безпеки діють при роботі з AI. Містить кілька інтерактивних інструментів та фінальний тест на закріплення.

**Живий приклад:** відкрийте `index.html` у браузері, або опублікуйте через GitHub Pages (див. нижче).

## Структура проєкту

```
├── index.html        # вся розмітка та контент
├── css/style.css      # стилі й дизайн-токени
├── js/main.js          # анімації, термінал-ефект, інтерактивні блоки
└── README.md
```

Ніякої збірки не потрібно — це чистий HTML/CSS/JS. Бібліотеки (GSAP, ScrollTrigger, Typed.js, Lucide) підключені через CDN прямо в `index.html`.

## Розділи сайту

1. **Хіро** — термінал-ефект завантаження
2. **Контекст** — реальна статистика (Gallup, Cyberhaven, Founder Reports 2026)
3. **Корпоративний GPT** — головний інструмент, кроки старту
4. **Який AI обрати** — порівняння ChatGPT/Claude/Copilot/Gemini + інтерактивний підбір під задачу
5. **AI-словник** — глосарій термінів (акордеон)
6. **Як писати промт** — формула + 3 розгорнуті приклади + **конструктор промтів**
7. **Безпека** — золоте правило, що не можна відправляти, **реальний кейс Samsung (2023)**, **перевірка тексту на ризики**, сканер ризиків
8. **Шпаргалка** — фінальний чек-лист
9. **FAQ** — часті запитання (акордеон)
10. **Тест** — 10 запитань з живим підрахунком балів і підсумковою оцінкою

## Інтерактивні інструменти

- **Підбір AI під задачу** — клік по типу задачі → миттєва рекомендація інструменту
- **Конструктор промтів** — форма (роль / тип завдання / тон / обсяг / тема) → готовий промт + кнопка "Копіювати"
- **Сканер ризиків** — клік по прикладу даних → вердикт "можна / не можна"
- **Перевірка тексту** — вставляєте текст запиту → сканування на паролі, номери карток, ризикові слова
- **Фінальний тест** — 10 запитань, підсвітка правильної/неправильної відповіді, підсумкова оцінка, кнопка "Пройти ще раз"

## Як опублікувати на GitHub Pages

1. Створіть новий репозиторій на GitHub і завантажте туди всі файли з цієї папки.
2. У репозиторії відкрийте **Settings → Pages**.
3. У розділі **Branch** оберіть `main` (або `master`) і папку `/root`, натисніть **Save**.
4. Через 1–2 хвилини сайт буде доступний за адресою:
   `https://<ваш-username>.github.io/<назва-репозиторію>/`
5. Посилання можна розсилати всім співробітникам — доступ відкритий, встановлення не потрібне.

## Як редагувати контент

- Текст і структура секцій — у `index.html` (кожна секція позначена коментарем `<!-- ============ НАЗВА ============ -->`).
- Кольори, шрифти, відступи — змінні на початку `css/style.css` (`:root { ... }`).
- Приклад: щоб змінити основний акцентний колір, відредагуйте `--primary` у `css/style.css`.
- Приклади промтів для секції "Як писати промт" — атрибути `data-text` на елементах `.typing-target` в `index.html`.
- Питання тесту — блоки `.quiz-question` в `index.html`, атрибут `data-correct` вказує індекс правильної відповіді (рахунок з нуля).
- Слова, які шукає перевірка тексту — масив `flagWords` в `js/main.js`.

## Форма фідбеку

Кнопка **«Фідбек»** в шапці відкриває модальне вікно з формою (ім'я, оцінка 1–5, коментар). Дані шле напряму в Google Таблицю через безкоштовний Google Apps Script — без окремого бекенду.

**Налаштування (один раз):**

1. Створіть нову Google Таблицю — назвіть перший аркуш, наприклад, `Feedback`.
2. У таблиці: **Розширення → Apps Script**.
3. Вставте туди такий код (замінює вміст файлу за замовчуванням):

   ```javascript
   function doPost(e) {
     const sheet = SpreadsheetApp.getActiveSpreadsheet().getSheetByName('Feedback');
     const data = JSON.parse(e.postData.contents);
     sheet.appendRow([
       new Date(),
       data.name || '',
       data.rating || '',
       data.comment || '',
       data.page || '',
     ]);
     return ContentService.createTextOutput(JSON.stringify({ status: 'ok' }))
       .setMimeType(ContentService.MimeType.JSON);
   }
   ```

4. **Deploy → New deployment → Web app**.
   - Execute as: **Me**
   - Who has access: **Anyone** (потрібно, щоб фронтенд міг слати запити без логіну)
5. Скопіюйте URL веб-застосунку (`https://script.google.com/macros/s/.../exec`).
6. Вставте цей URL у [js/main.js](js/main.js) замість `PASTE_YOUR_GOOGLE_APPS_SCRIPT_WEB_APP_URL_HERE` (константа `FEEDBACK_ENDPOINT` на початку файлу).

Поки URL не вставлено, форма показує зрозуміле повідомлення замість спроби відправки в нікуди.

**Обмеження підходу:** Apps Script Web App не повертає CORS-заголовки, тому запит відправляється в режимі `no-cors` — фронтенд не може прочитати відповідь і бачить лише сам факт відправки, без підтвердження, що рядок дійсно з'явився в таблиці. Для внутрішнього інструмента це прийнятний компроміс; якщо потрібна гарантована доставка й читання статусу — знадобиться повноцінний бекенд.

## Технології

- **GSAP + ScrollTrigger** — анімації елементів при скролі
- **Typed.js** — термінал-ефект у хіро-секції
- **Lucide** — іконки
- Ванільний JS (без фреймворків) — усі інтерактивні інструменти

## Доступність

- Враховано `prefers-reduced-motion` — анімації вимикаються для користувачів, які цього потребують
- Контраст тексту відповідає WCAG AA
- Сайт адаптивний: мобільні, планшети, десктоп
- Акордеони (глосарій, FAQ) побудовані на нативному `<details>` — працюють без JS і з клавіатури
